# Railway with an external OIDC provider

Railway is an alternative Docker host for the **ForgetMeNote app**. It does not run the standalone Compose bundle directly. Supply a separate reachable OIDC provider (managed or your own Authelia), rather than duplicating the bundled stack's authentication service inside an app deployment.

1. Deploy the repository's Dockerfile as one service. Attach a persistent Railway volume at `/data`. Keep one replica and ensure deployments stop the previous writer before starting its replacement. The catalog lock rejects concurrent writers; plan for brief downtime.
2. Configure the public HTTPS domain and exact `PUBLIC_URL`, internal target port 8080, `OIDC_ISSUER_URL`, and `OIDC_CLIENT_ID`. Register `/auth/oidc/callback` with the provider. The app listens on `:8080`; either use that Railway target port or set `LISTEN_ADDR` explicitly to the platform port.
3. Place the OIDC secret in a mode-0600 file readable by the app's Unix user, for example `/data/secrets/oidc-client-secret`, through a secure operator console/file-provisioning process. Set `OIDC_CLIENT_SECRET_FILE` to it. Railway environment variables are not Docker secrets or files: configuring a variable alone does not create this file. Do not bake the secret into the image or put it into repository content. If your platform workflow only provides secret variables, supply a private startup wrapper that writes the file with `umask 077` without echoing it before executing ForgetMeNote; no platform-specific wrapper is included here.
4. Ensure volume ownership permits writes by the image's UID (1000 by default). Provision/restore data before starting the writer. Do not place Git, authentication state, or secrets on the ephemeral image filesystem.
5. Sign in once to provision your user, then use private recovery access to grant that verified User ID Admin in ForgetMeNote. Configure remaining project roles in the app. Existing-account linking and offboarding follow [authentication](authentication.md).

Use volume snapshots plus separately protected configuration/secrets and periodically restore into an independent instance. Git remotes remain optional and are not a complete backup. Preserve the public issuer when restoring; do not assume a volume clone is safe to run concurrently against the same remote/service identity.

Railway-specific domain routing, secret provisioning, volume ownership, deployment overlap and backup restoration were not tested from this development machine. Consult current [volume documentation](https://docs.railway.com/volumes) and the platform's service/networking controls before deployment. This guide distinguishes required platform setup from the tested ordinary-host Compose preset; no Railway resources were created.
