# Email, Google Sheets and Google Calendar

These are reusable `email`, `sheets` and `calendar` kinds in `DATA_CONNECTIONS_CONFIG_FILE`. The Go server owns OAuth refresh, account verification, HTTP, MIME parsing, permissions and durable write outcomes. Packages use `connectors.read` / `connectors.submit`; API and MCP clients use the existing generic data tools. No Google client or credentials belong in Python, notebooks or Git.

Start with [the read-only configuration](../deploy/integrations/google/connections.example.json). Connection definitions remain file-managed. Administration → Connections manages operation grants, tests the authorized account, and inspects write outcomes; it does not overwrite operator files. Changes to the runtime file require a server restart. Grants are separate from OAuth scopes and from notebook membership. `projects` requires read access to **every** listed notebook, including client-credential project restrictions. For confidential connections set this explicitly, even when the Google data is not yet in a notebook.


## Provider-neutral email contract

Configure `kind: "email"` with `email: {provider: "gmail", mailbox: "…", workflow: "…", recipients: []}`. Gmail is the only implemented provider. Unknown or omitted providers are rejected at configuration load. Administration identifies the connection as Email · Gmail. This replaces the unpublished Gmail-only configuration; no production mailbox configuration has been migrated.

All clients use `messages`, `message`, `thread`, `attachment`, `selection`, `changes`, and separately granted draft/send operations. Message `flags` are normalized (`inbox`, `sent`, `draft`, `trash`, `spam`, `unread`, `starred`). A message/thread `revision` and a mailbox `cursor` are opaque strings scoped to the configured connection/account. Never compare them numerically or reuse them after changing providers/accounts. Preserve provider-specific source references for citations.

`status` returns `provider`, `cursor`, `capabilities` and configured operations. Capabilities describe adapter support, not permission: operation grants still apply. Finance requires `incrementalChanges`; automatic replies additionally require `threads`, `guardedReplies` and `drafts`/`send`. Gmail reports `atomicThreadPreconditions: false`. `maxPageSize` reports the provider's page limit, not a limit on total ingestion. Packages retain unfinished pages for later runs.

`changes {cursor, pageToken?, pageSize?}` returns normalized `changes: [{id, kind: "upsert" | "deleted"}]`, `cursor`, `nextPageToken`, `hasMore`, `complete` and possibly `expired`. A change page's cursor must not replace the saved cursor until its work and remaining pages are processed. Capture `status.cursor` before a full scan. An expired cursor requires an explicit rescan with coverage gaps; deletion can make old evidence unrecoverable.

`messages` and `selection` accept `filter`: `after`/`before` (RFC3339 at whole-second precision), `from`/`to` (single mailbox addresses), `subject` (phrase), `flags`, `excludeFlags`, `hasAttachment`. Gmail maps these to its search operators; subject phrases containing quotes/backslashes/control characters and unsupported filters fail explicitly. Structured filters are content selection, never authorization. Dates use epoch seconds to preserve timezone semantics. See [Gmail filtering](https://developers.google.com/workspace/gmail/api/guides/filtering).

Advanced selection accepts `providerQuery: {provider: "gmail", query: "label:finance"}`. It is explicitly provider-specific and rejected for a different provider. Finance forwards this optional configuration without interpreting it. Generic workflows need no Google response fields, query construction or label parsing. Future adapters must implement and test this contract, including permission, identity and uncertain-write behavior, before becoming configurable; there is no alternate execution service or provider SDK in Python.


## Google setup

1. Confirm the source identity. A Gmail mailbox is an actual Google account with Gmail enabled. An alias delivers into another mailbox; authorize and configure that underlying mailbox. A Google Group is not a Gmail mailbox. Delegated Gmail UI access does not make the delegate's OAuth token the mailbox owner's token. This adapter uses `users/me` and requires authorization by the configured mailbox account; it adds neither impersonation nor domain-wide delegation. The real Finance address/type is **not yet verified**.
2. In an operator-owned Google Cloud project, enable the Gmail, Sheets and/or Calendar API. Configure the consent screen and OAuth client. For a single Workspace organization, consider an **Internal** application and its administrator's API-access policies. External distribution may require verification and, for restricted scopes, a security assessment. External applications left in Testing can have short-lived refresh grants. Review Google's current rules before selecting an audience.
3. Obtain offline authorization from the intended account using an approved operator OAuth flow and the client type's exact registered redirect URI. Google login to ForgetMeNote is a different grant and is not reused. Consent, scopes and the actual mailbox identity require administrator action for a pilot; this implementation does not connect any account automatically.
4. Save the client secret and refresh token as runtime secret values referenced by `clientSecretEnv` / `refreshTokenEnv`, or use absolute `clientSecretFile` / `refreshTokenFile` paths outside the workspace (private permissions). In Docker/Kubernetes use secret mounts or secret-backed environment variables. Never put values in the config JSON, package parameters or notes. Separate mail and Sheets tokens can use the same OAuth client. The existing refresh mechanism supports nonrotating Google refresh tokens; unexpected token rotation reports an operator action rather than losing the replacement token.
5. Configure exact account email, operation names, spreadsheet ID, tab IDs/ranges, notebook restrictions and recipient addresses. Create a dedicated service account with only needed notebook and connector grants. The status operation only reads account identity; it is not a test send. It reports configured operations and whether scopes were reported, not an invented assurance that every resource is accessible. Inspect permitted operation discovery as the intended caller and test an allowed read separately.
6. A 401 prompts reauthorization and invalidates the cached access token. Refresh `invalid_grant`/`invalid_client` prompts replacing the runtime credential reference. A 403 identifies missing scopes or resource access. An account mismatch fails closed. Authorization and account checks run again before returning cached write receipts; host permissions are rechecked before each Google request and after execution.

| Capability | OAuth scopes | Explicit ForgetMeNote operation grants |
|---|---|---|
| Mail search, messages, threads, attachments, history, account status | `https://www.googleapis.com/auth/gmail.readonly` | `status`, `messages`, `message`, `thread`, `attachment`, `changes`, `selection`, each separately |
| Create/read/update workflow drafts | Read scope above plus `https://www.googleapis.com/auth/gmail.compose` | `draft-create`, `draft`, `draft-update` |
| Send a source-backed reply | Read scope above plus `https://www.googleapis.com/auth/gmail.send` | `send` |
| Send a workflow draft | Read + compose (which includes provider send authority) | `draft-send` |
| Read spreadsheet and verify account | `openid`, `email`, `https://www.googleapis.com/auth/spreadsheets.readonly` | `status`, `metadata`, `read` |
| Write a configured spreadsheet area | `openid`, `email`, `https://www.googleapis.com/auth/spreadsheets` | `update`, `append`, separately |
| List a configured calendar's events and verify account | `openid`, `email`, `https://www.googleapis.com/auth/calendar.events.readonly` | `status`, `events` |

`gmail.compose` is **not draft-only at Google**: it also authorizes sending. ForgetMeNote enforces its separate send grants. Sheets scopes apply across accessible spreadsheets, not individual tabs. The adapter enforces the configured spreadsheet, numeric tab ID and quoted A1 area on every request. Gmail queries/labels select messages; they do not isolate a mailbox or prevent an otherwise authorized reader from reading another message in it. Grant mailbox access accordingly. Generic Google connections are excluded from shared usage/profile-learning capture.

References: [Gmail scopes](https://developers.google.com/workspace/gmail/api/auth/scopes), [Sheets get/scopes](https://developers.google.com/workspace/sheets/api/reference/rest/v4/spreadsheets/get), [OAuth web-server/offline access](https://developers.google.com/identity/protocols/oauth2/web-server), [Gmail synchronization](https://developers.google.com/workspace/gmail/api/guides/sync).

## Read contract

Discover schemas with `list_data_operations`. IDs/cursors are opaque strings. `messages` and `changes` return one explicit page (`nextPageToken`, `hasMore`). A page's `complete` does not mean the whole selection is exhausted. Gmail history 404 returns `expired:true`; rescan the selected scope from a new pre-scan anchor and report gaps. `selection` reevaluates the actual query using the message's RFC Message-ID and verifies the provider message ID. Missing/unsearchable messages remain explicit uncertainty.

Messages contain account, IDs, timestamps, relevant headers, sender/recipients, labels, source references, decoded text with quoted segments, attachment metadata, unsupported content and completeness. Multipart alternatives appear once. HTML becomes inert text: no rendering, scripts or tracking-image fetch. `attachment` retrieves one referenced body as base64; `documents.extract` is the existing extraction owner. Unsupported/omitted content is never silently considered understood. Encrypted content is not decrypted by the adapter.

Sheets reads use explicit quoted A1 ranges (for example `'Invoices'!A1:J100`). Named/ambiguous/unquoted ranges fail closed. A multi-range read validates every range before requesting spreadsheet data. Cells retain `userEnteredValue`, `effectiveValue`, `formattedValue` and `present` (omitted trailing cell versus a returned empty cell). Locale, timezone and numeric tab ID accompany reads. Split large tables into explicit ranges within configured `maxRows` / `maxBytes`; exceeding a budget fails rather than silently truncating.

## Calendar

A `calendar` connection reads one calendar and nothing else: `calendar: {account: "…", calendar: "…"}` names the authorized account and the calendar ID, as shown in Google Calendar's **Settings and sharing → Integrate calendar** (for example `c_…@group.calendar.google.com`). The account needs read access to that calendar. Its operations are `status` and `events`; it has no writes.

`events {from, to, pageToken?}` lists the events between two dates, `YYYY-MM-DD`, from 1 to 366 days apart, with recurring events expanded. Each event has only `id`, `title`, `allDay`, `start` and `end`: an all-day event has dates with an exclusive end, as Google stores them; others have RFC 3339 times. Descriptions, attendees, locations and cancelled events are never requested or returned. A page holds up to 250 events; `hasMore` and `nextPageToken` continue it. The response also names the `calendar` and its `timeZone`.

Google's public holiday calendars are read the same way; for United States public holidays only, the ID is `en.usa.official#holiday@group.v.calendar.google.com`. The [task reminder](tasks.md#the-weekday-reminder) uses calendar connections to skip holidays. Leave `externalProcessing` false unless event titles may reach AI providers.

## Writes and uncertainty

A Google write requires `data:write`, its operation grant and durable automation storage, even when invoked directly through API/MCP. Conversational tools remain unable to write. Arguments include a stable `actionID`; it is an application receipt key, **not a Google idempotency guarantee**. A receipt belongs to the identity that recorded it: another caller reusing the same `actionID` and input is refused instead of receiving that outcome. The shared owner durably records intent before any provider write and saves validated provider IDs/ranges afterward. Google operations use adapter-owned preconditions/acknowledgments; unlike existing generic HTTP submissions they do not require callers to predict provider-generated IDs. Existing HTTP guard/acknowledgment behavior is unchanged.

Outcomes are rejected (validation/preflight or an explicit provider rejection), accepted (valid API acknowledgment), and unknown (possible submission without a trustworthy acknowledgment). A Gmail message ID means API acceptance, **not recipient delivery**. A crash after success but before saving the receipt is unknown. Unknown/started effects block **all new write identities on that connection**, including different jobs, step IDs and direct calls. The same completed identity replays its receipt after fresh permission/account checks; changing its payload fails. There are no automatic write retries.

Administrators inspect `data_connection_effects {connection}` and perform read-only reconciliation using message/thread/draft reads, Gmail `rfc822msgid:` search (generated Message-ID hashes the configured workflow and actionID), or the output sheet's business identity. Absence from a search is inconclusive. `resolve_automation_effect {id,state,evidence}` records a verified `accepted`/`rejected` result, never resubmits. It requires a concrete evidence note; it does not manufacture a provider receipt. After reconciliation, inspect/cancel an interrupted run separately. Neither cancelling nor history expiry deletes the effect barrier. Accepted effect IDs and unknown reconciliation metadata remain private and durable.

Drafts require the configured `X-ForgetMeNote-Workflow` marker. Updates/sends check the current fingerprint. Reply sends require an eligible source message, allowed original sender, matching subject/References, and a fresh opaque `threadRevision`; automated notices, self replies, other drafts and newer messages block the action. Recipients must be exact operator-allowed addresses. New draft mode and send mode are separately granted. Google does not provide an atomic draft/thread conditional operation: a human or new message can still race the final preflight. These checks reduce conflicts; they do not provide confinement or exactly-once delivery.

Sheet writes accept RAW string rows, preserving leading zeros and keeping `=...` text from becoming a formula. `range` is the allowed lookup table, `identityColumn` is relative/one-based, `identity` must remain in the new row, and `expected` is the prior full cell-object row. The host finds the identity again and compares values immediately before writing; moved rows work, duplicates/changes fail. The response's actual updated range, values and cell count must match. `atomic:false` explicitly records the remaining GET/PUT race. Do not use this as transactional protection of collaborative operational cells.

Append is permitted only with `write:true`, `append:true`, `automationOwned:true` and an entire-tab column area starting at A, matching the tab's current column count (for example `'Automation output'!A:E`). The eventual row can grow but cannot escape that tab/column policy. It verifies the business identity is absent before submitting and validates the actual returned area. A collaborator can still race the check; keep the output tab automation-owned. Operational invoice corrections default to notebook proposals.

## Private recovery and retention

`jobstate.get/set` is atomic CAS state keyed by job, actor and project. It survives scheduler restarts and run pruning; an exact crash-after-save replay is idempotent. Preview uses a private in-run overlay. Scripts cannot select another job's state. Source/selection/config invalidation belongs to the package, not an opaque mailbox database.

Set `script.retentionHours` to 1–168 (the Finance example uses 24). Finished or interrupted journals expire from run creation after active execution finishes; the ordinary scheduler prunes them. Step inputs, connector bodies, attachments, extraction text, model arguments/results and generated replies are redacted. Expired runs cannot resume their raw journal. Minimal hashes/statuses remain, including unresolved effects. Run recovery data and job state stay outside notebook Git.

Retention-enabled script records use queue version 8 so older readers cannot
resume redacted checkpoints. Do not roll back to an older binary against those
records; preserve current private state for forward recovery. Existing record
versions remain readable by this implementation.

`ai.structured` and `decision.evaluate` optionally accept `cacheKey`. The shared private owner binds it to job/actor/project, exact input and provider/model configuration across runs. Results expire within the journal window; an already-attempted key without retained results is not silently billed again. Packages retain only necessary normalized findings within their reporting window. An unknown paid call also blocks the job's analysis scope until reconciled; inspect `automation_effects {id}` and use the same administrator resolution action. Cache identifiers should include source content, policy/template and schema identity. Typed choices/confidence are not financial evidence.

The Finance package prunes normalized findings when it runs, retains cursor/action identities separately, and never writes mailbox cursors or raw mailbox copies to its notebook. Pausing a job stops that package-level reporting-window cleanup; retain only necessary normalized state and include manual cleanup in decommissioning. The private effect journal remains until reconciliation. Private state is administrator-readable; Python packages are trusted administrator-installed code sharing the server OS identity. Host permissions protect cooperative calls; neither Python nor a venv confines malicious code.

Backups may retain older private journals until their own retention expires. Deleting a note does not remove it from notebook Git history or backups. Scope external AI consent explicitly for the Finance sources and notebook; external providers have their own retention. Do not grant these connectors/notebooks to workspace-wide Slack identities, broad summaries or unrelated automation accounts.
